## 고도화(검토 완료, 착수 보류): 거래 자동 반영 — 안드로이드 알림 캡처 브리지
카드 결제 내역을 수동 입력 대신 자동으로 월 실적·사용액에 반영하기 위한 계획. **앱이 안정화된 뒤 착수.**

**핵심 아이디어**: 캡처는 안드로이드(갤럭시)에서만 하고, 저장은 Firestore 중앙에, 조회는 CardFit(PWA)이 공통으로 읽음 → **아이폰·갤럭시 어디서든 조회 가능**(아이폰은 캡처하지 않고 갤럭시가 올린 데이터를 읽어 표시만).

**구조**
1. 갤럭시가 카드 결제 알림(카드사 푸시/SMS)을 수신.
2. 안드로이드 캡처 에이전트(무코드: MacroDroid/Tasker + AutoNotification, 또는 소형 네이티브 앱)가 알림 문구에서 `금액·가맹점·카드·시각`을 파싱.
3. 웹훅(Firebase Cloud Function 또는 Google Apps Script)으로 POST → 웹훅이 본인 인증으로 Firestore `users/{uid}/transactions`에 기록. (Tasker가 Firestore에 직접 쓰는 인증이 번거로워 웹훅 경유를 권장)
4. CardFit(PWA)이 `transactions`를 읽어 카드/업종 매핑 후 월 실적·사용액에 반영.

**전제·제약**
- 결제 알림이 **실제로 갤럭시에 도착**해야 함(카드앱 로그인 위치/SMS 등록번호 확인). 아이폰만 들고 결제 시 갤럭시 미수신이면 누락 → CSV 명세서 업로드로 월말 보완.
- 갤럭시 상시 켜짐 + 캡처 에이전트 백그라운드 상시 실행(배터리 최적화 예외 설정).
- **iOS는 타 앱 알림 읽기가 원천 불가**하므로 캡처는 안드로이드 전용(iOS는 조회만).
- **마이데이터/오픈뱅킹은 사업자 허가·보안 인프라가 필요**해 개인 PWA 범위 밖 → 제외.
- 보안: 카드번호 전체 등 민감정보 저장 금지(금액·가맹점·마스킹 카드명 수준). 본인 Firestore만 사용(`firestore.rules`로 본인 R/W 제한).

**CardFit 신규 개발 범위**: `transactions` 컬렉션 읽기, 카드/업종 자동 매핑 규칙, 월 실적·사용액 반영, 중복 방지 키(카드+금액+시각)와 수정 UI.
