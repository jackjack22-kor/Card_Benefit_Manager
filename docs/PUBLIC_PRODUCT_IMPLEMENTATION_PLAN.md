# CardFit 공개판 구현 마스터 플랜

## 목적

이 문서는 CardFit을 개인용 서비스와 공개 배포판으로 안정적으로 이원화하기 위한 실행 기준서입니다. 앞으로 공개판 기능, 카드 데이터, 광고, 배포, 문서, 테스트를 추가할 때 이 문서를 우선 확인합니다.

핵심 원칙은 간단합니다.

- 개인용 서비스는 현재 Firebase Hosting과 Firebase Auth/Firestore 동기화를 유지합니다.
- 공개판은 Cloudflare Pages와 고정 도메인에서 동작하며, 사용자 데이터는 브라우저 localStorage와 JSON 백업에만 둡니다.
- 어떤 데이터든 사용자가 최종 입력한 값이 기본값, 원격값, 마이그레이션, 새 카드 데이터 때문에 되돌아가면 안 됩니다.
- 공개판 카드 데이터는 공식 출처 확인과 감사 테스트 없이 대량 추가하지 않습니다.

## 이미 결정한 사항

| 영역 | 결정 |
| --- | --- |
| 배포 구조 | 개인용 Firebase Hosting, 공개판 Cloudflare Pages |
| 공개판 도메인 | 고정 도메인을 Cloudflare Pages에 연결 |
| 에디션 분리 | `VITE_APP_EDITION=personal/public` |
| 개인용 저장 키 | `cardBenefitManager.v1` 유지 |
| 공개판 저장 키 | `cardfit.public.v1` |
| 공개판 동기화 | Firebase 런타임과 클라우드 동기화 UI 비활성화 |
| 공개판 데이터 보관 | localStorage + JSON 백업 |
| 카드 이미지 | `image/clean/*.png` 가로형 이미지 사용 |
| 회귀 방지 | `npm run audit:check`, `npm run build:pages`, `npm run build:public` 통과 후 커밋 |
| 공개판 산출물 검증 | `build:public`에서 `verify:public`을 함께 실행해 `dist` 기준으로 Cloudflare 파일, 이미지, 저장 키, 동기화 코드 제외 여부 확인 |
| 카드 데이터 출처 | 공식 상품 페이지와 상품설명서 PDF 우선 |

## 아직 열어둘 사항

| 영역 | 결정 조건 | 산출물 |
| --- | --- | --- |
| 공개 도메인 이름 | 실제 구매/연결 가능한 도메인 확인 후 결정 | Cloudflare Pages custom domain 설정 기록 |
| 광고 플랫폼 | Google AdSense 승인 요건, 개인정보/쿠키 고지, 광고 배치 정책 확인 후 결정 | 광고 적용 계획 문서, 공개판 전용 광고 플래그 |
| 카드 대량 추가 범위 | 공식 출처 확인이 쉬운 카드부터 단계별 추가 | 카드사별 리서치 배치, 감사 케이스 |
| 네트워크별 카드 모델 | VISA/Mastercard/AMEX 차이가 계산에 영향 주는지 확인 후 결정 | `networks` 필드 또는 별도 카드 ID |
| 공개판 약관/고지 | 광고/분석/쿠키 사용 여부 확정 후 작성 | 개인정보처리방침, 이용 안내 |

## 작업 단계

### 0단계: 안전 기반 고정

상태: 진행 중, 대부분 완료

목표는 개인용과 공개판의 데이터 저장/동기화 경로를 확실히 분리하고, 사용자 입력값이 원복되지 않는 기반을 유지하는 것입니다.

완료 기준:

- 개인용 기본 저장 키 유지
- 공개판 별도 저장 키 사용
- 공개판 Firebase 동기화 비활성화
- 카드 상세 설정의 월/연간 실적, 연회비 시작월, 포인트 가치, 사용 실적 병합이 사용자 최종 입력값을 우선
- 카드/혜택/이미지 필수 품질 게이트 적용
- `npm run audit:check` 통과

### 1단계: 공개판 운영 골격

상태: 진행 중

목표는 Cloudflare Pages에서 바로 배포 가능한 산출물과 운영 문서를 갖추는 것입니다.

작업:

- `build:public` 유지
- `dist/_redirects`, `dist/_headers`, `image/clean` 복사 유지
- `verify:public`로 공개판 산출물을 직접 검증
- Cloudflare Pages 설정 절차 문서화
- 공개판 설정 화면의 로컬 저장/백업 안내 유지
- 공개판 번들에 Firebase 동기화 청크가 없는지 확인

완료 기준:

- `npm run build:public` 통과
- `npm run verify:public` 통과
- 공개판 `dist`에서 `syncManager` 미검출
- Cloudflare Pages 프로젝트 생성 후 첫 배포 성공
- 고정 도메인 연결 성공

### 2단계: 카드 데이터 관리 체계

상태: 진행 중

목표는 카드 데이터를 빠르게 늘리기 전에 출처, 모델링, 감사 기준을 먼저 고정하는 것입니다.

작업:

- 현재 카드 18장의 공식 출처 재검증
- `sourceNote`를 구조화된 `source` 필드로 확장할지 검토
- 제휴 브랜드 차이 모델링 방식 결정
- 카드 추가 후보를 카드사별 배치로 나누기
- 카드 추가마다 대표 산식 감사 케이스 추가

완료 기준:

- `docs/CARD_DATA_SOURCE_MATRIX.md`에 모든 카드 ID 존재
- 모든 카드에 이미지, 출처 메모, 필수 혜택 설명 존재
- 신규 카드마다 최소 1개 이상 계산/표시 감사 케이스 존재
- 공식 출처 확인일 기록

### 3단계: 공개판 UX 정리

상태: 예정

목표는 “설치 후 바로 내 카드 목록을 골라 쓰는 앱”으로 정리하는 것입니다.

작업:

- 첫 실행 시 카드 선택/숨김 흐름 개선
- 공개판 기본 카드 목록과 선택 카드 목록 분리 검토
- 카드 검색/필터 개선
- JSON 백업 안내를 과하지 않지만 놓치기 어렵게 유지
- 추천 화면에서 카드 조건의 불확실성 또는 공식 확인일 노출 검토

완료 기준:

- 신규 사용자가 카드 추가/숨김/정렬을 설정 화면에서 자연스럽게 수행
- 모바일에서 주요 CTA와 입력 필드가 겹치지 않음
- 공개판에서 클라우드 동기화 표현이 남지 않음

### 4단계: 카드 데이터 1차 확장

상태: 예정

목표는 공개판 사용자가 처음 들어왔을 때 “내 카드가 아예 없다”는 느낌을 줄이는 것입니다.

우선 후보:

- 신한: SOL트래블, Deep Dream, Mr.Life 계열
- 현대: ZERO Edition, M/MX 계열
- KB국민: WE:SH, My WE:SH, 탄탄대로 계열
- 삼성: iD, taptap 계열
- 우리: DA@카드, 카드의정석 계열
- 롯데: LOCA LIKIT, LOCA 365 계열
- 하나: MULTI, JADE 계열
- BC: 바로카드 생활/여행형

완료 기준:

- 카드사별 공식 출처 확인
- 이미지 정규화
- 추천/혜택 계산 테스트 추가
- 기본 노출/숨김 정책 결정

### 5단계: 광고와 공개 고지

상태: 예정

목표는 공개판에만 광고를 붙이고 개인용에는 광고 코드를 넣지 않는 것입니다.

작업:

- Google AdSense 또는 대체 광고 플랫폼 공식 요건 확인
- 공개판 전용 광고 플래그 추가
- 광고 컴포넌트 위치 결정
- 개인정보처리방침/쿠키/광고 식별자 고지 작성
- 광고가 카드 추천/입력 흐름을 방해하지 않는지 확인

완료 기준:

- 개인용 빌드에 광고 스크립트 미포함
- 공개판 빌드에만 광고 코드 포함
- 광고 미승인/차단 상태에서도 앱 기능 정상 동작
- 정책 문서와 앱 안내 문구 반영

### 6단계: 공개 배포와 운영

상태: 예정

작업:

- Cloudflare Pages 프로젝트 연결
- 고정 도메인 연결
- 첫 공개 배포
- 모바일 설치 테스트
- 브라우저별 localStorage/백업/복원 확인
- 배포 체크리스트 문서 갱신

완료 기준:

- iPhone Safari 홈 화면 추가 성공
- Android Chrome 또는 Samsung Internet 설치 성공
- PC 브라우저에서 백업/복원 성공
- 도메인 변경 없이 재배포 가능

## 브랜치와 커밋 운영

현재는 `main`에서 작업하되, 배포 위험이 큰 작업은 별도 브랜치를 사용합니다.

권장 기준:

- 문서/감사/작은 UI 개선: `main` 직접 커밋 가능
- 카드 데이터 대량 추가: `codex/card-data-*` 브랜치 권장
- 광고/외부 스크립트: `codex/public-ads-*` 브랜치 권장
- 배포 설정 변경: `codex/cloudflare-*` 브랜치 권장

커밋 전 필수 확인:

```bash
npm run audit:check
npm run build:pages
npm run build:public
npm run verify:public
git diff --check
```

## 데이터 원복 방지 체크리스트

새 기능이 다음 데이터 중 하나라도 건드리면 원복 가능성을 별도로 검토합니다.

- `cardOverrides`
- `monthlyCardUsage`
- `usage`
- `settings.pointValues`
- `cardOrder`
- `hiddenCardIds`
- `backupMeta`
- 향후 추가될 `source`, `networks`, 사용자 선택 카드 목록

원칙:

- 기본값은 빈 상태를 채우는 데만 사용합니다.
- 사용자가 수정한 값에는 명시 플래그 또는 타임스탬프를 둡니다.
- import, migration, sync merge는 항상 사용자 최종값을 우선합니다.
- 공개판은 원격 병합이 없지만, import/초기화/새 카드 추가가 기존 값을 덮지 않아야 합니다.
