# 카드 데이터 리서치 기준

## 목표

공개판 CardFit의 카드 데이터는 사용자가 실제 결제 판단에 참고할 수 있을 만큼 출처, 혜택 조건, 실적 기준, 제휴 브랜드 차이를 명확하게 관리해야 합니다.

카드 데이터는 빠르게 낡을 수 있으므로, 추가 또는 수정 시점의 공식 출처를 확인하고 변경 이력에 남깁니다.

현재 카드별 출처 확인 상태와 추가 후보군은 `docs/CARD_DATA_SOURCE_MATRIX.md`에서 추적합니다.

## 우선 출처

1. 카드사 공식 상품 페이지
2. 카드사 공식 상품설명서 PDF
3. 카드사 앱/고객센터 공지에서 확인되는 변경 공지
4. 제휴 브랜드 공식 안내 페이지

블로그, 커뮤니티, 광고성 비교 페이지는 후보 발굴용으로만 사용하고, 최종 수치는 공식 출처로 재확인합니다.

## 필수 수집 항목

- 카드사
- 카드명
- 카드 이미지
- 연회비
- 국내/해외 또는 VISA/Mastercard/AMEX/UnionPay 등 제휴 브랜드별 연회비 차이
- 전월 실적 기준
- 연간 실적 기준
- 발급월/연회비 시작월 기준
- 주요 혜택별 적립률 또는 할인율
- 월/연 한도
- 건별 최소 결제금액
- 제외 업종
- 실적 산정 제외 항목
- 신규 발급월 혜택 조건
- 서비스 제공 주기
- 공식 출처 URL 또는 PDF명
- 확인일

## 카드 이미지 기준

이미지는 실제 카드 식별이 가능해야 합니다. 앱에는 `image/clean` 아래 가로형 PNG로 정규화해 넣습니다.

이미지 추가 시 다음을 확인합니다.

- 카드명과 이미지가 같은 상품인지
- 제휴 브랜드 디자인이 다른 경우 어떤 브랜드 이미지인지
- 투명 배경 또는 흰 배경에서 카드가 잘리는 부분이 없는지
- 모바일 카드 상세 화면에서 가독성이 유지되는지

## 제휴 브랜드 차이 모델링

같은 카드라도 VISA, Mastercard, AMEX 등 브랜드에 따라 다음 항목이 달라질 수 있습니다.

- 연회비
- 국내외 결제 가능 브랜드
- 공항 라운지, 발레파킹, 호텔, 다이닝 같은 국제 브랜드 서비스
- 해외 수수료 또는 해외 이용 관련 혜택
- 카드 이미지

차이가 계산에 영향을 주면 카드 데이터를 별도 카드 ID로 나누거나, 카드 객체에 브랜드 옵션 구조를 추가합니다. 단순 안내 차이면 혜택 `summary`, `conditions`, `sourceNote`에 명확히 적습니다.

## 반영 절차

1. 후보 카드 목록을 카드사별로 정리합니다.
2. 공식 페이지와 PDF를 확인합니다.
3. 혜택을 계산 가능한 항목과 안내용 항목으로 나눕니다.
4. `src/data/cards.js`에 카드와 혜택을 추가합니다.
5. 카드 이미지를 `image/clean`에 추가합니다.
6. 계산 로직이 필요한 혜택은 `src/lib/recommend.js` 패턴에 맞춰 모델링합니다.
7. `tools/audit-check.mjs`에 대표 계산 시나리오와 이미지 존재 여부를 추가합니다.
8. `CHANGELOG.md`에 확인 출처와 기준일을 남깁니다.
9. `npm run audit:check`와 공개/개인 빌드를 실행합니다.

## 추가 우선순위

1. 현재 앱에 이미 있는 카드의 공식 출처 재검증
2. 신한, 삼성, 현대, KB국민, 롯데, 우리, 하나, BC의 대표 프리미엄/마일리지/간편결제 카드
3. 대중적인 무실적 또는 낮은 실적 카드
4. 공개판 추천 정확도에 영향이 큰 커피, 간편결제, 통신, 교통, 해외, 호텔, 항공 카테고리 카드

## 보류 기준

다음 경우에는 카드 추가를 보류합니다.

- 공식 상품설명서가 없거나 확인일 기준 최신 여부가 불명확한 경우
- 혜택 조건이 너무 복잡해서 현재 모델로 오해를 만들 가능성이 큰 경우
- 이미지 출처가 불명확한 경우
- 단종 카드인데 공개판 기본 목록에 넣을 이유가 약한 경우
